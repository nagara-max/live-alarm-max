# 次の収益化アクション（提案・優先順位つき）

- 作成日：2026-11-21
- 作成：提案チーム
- 状態：提案のみ（このファイル以外は変更していません）
- 前提：`goods.html`（楽天 12 リンク・もしも a_id=5914685）、`guide/` 10 記事、⚙設定の応援リンク（`config.js` の `tipUrl` が空のため非表示）、HP の匿名統計（about.html の `send()`：`hp_view`/`hp_scroll`/`hp_cta`/`hp_faq`/`hp_leave`）は実装済み。Amazon は当面なし。
- 守ること：鳴動画面（`#ring`）・おやすみモード（`#standby`）には何も置かない／アラームのロジック（`tick`・`fire`・`startStandby`・`#rClose` の処理など）に触れない／index.html に外部の広告スクリプトを入れない／YouTube API の規約に触れることはしない／誤認させる表示はしない。

## 調べてわかったこと（判断の根拠）

1. **goods.html と guide/ には統計が1行も入っていない。** about.html だけが `send()` を持つ。今は「グッズページが何回見られ、どのリンクが何回押されたか」がまったく分からない（もしもの管理画面ではクリック数は見えても、どのページ・どの記事から来たかは分からない）。
2. **記事の中に紹介リンクが無い。** 10 記事はどれも goods.html へのリンク（1〜2個）だけ。検索から来る人は記事に着地するので、goods.html まで1クリック余計にかかっている。
3. **アラームを閉じた後は、まだ有効なアラームがあればそのまま `startStandby()`（おやすみ画面）へ行く**（`#rClose` の処理）。つまり「アラーム後の画面にリンク」は、ほぼ禁止区域（`#standby`）か、`#rClose` の処理を変えることになる → 不採用。
4. index.html の `app_open` はすでに `utm_source`/`utm_medium`/`utm_campaign` を記録している。→ アプリへの流入は URL に utm を付けるだけで測れる。
5. **FAQPage の構造化データ（JSON-LD）は効果が見込めない。** Google は 2023 年 8 月から FAQ のリッチリザルトを政府・医療系などの権威あるサイトに限定した。about.html に入れても検索結果の見た目は変わらない → 不採用。
6. privacy.html 4章と about.html の FAQ「広告はありますか？」は「紹介リンクは goods.html だけ」と書いている。記事に紹介リンクを入れる時は、この2か所の文言も直す必要がある。

## 検討して外したもの

| 案 | 外した理由 |
|---|---|
| アラームを閉じた後の画面にグッズへのリンク | 有効なアラームが残っていれば閉じた後は `#standby` に行く（禁止区域）。そうでない場合だけ出すには `#rClose` の処理を変える必要がある（アラームのロジック） |
| トップ画面に昼間だけグッズへのリンク | 昼間にアプリを開く人は少なく効果が小さい。時刻判定の JS をアプリ内に足すことになる。ホーム画面版（standalone）で同じ画面のまま goods.html に移ると、夜に開いた時に goods.html のまま再開されて気づかず寝る恐れがある（帯で緩和はしているがゼロではない） |
| FAQPage／BreadcrumbList の JSON-LD | FAQ のリッチリザルトは 2023 年から権威サイト限定。パンくずはスマホの検索結果では表示されなくなっている。手間に対して効果がほぼない |
| 「推し活の朝」別ランディングページ | 広告を出して流入を買う予定がない以上、about.html と内容が重なり検索評価が割れるだけ。配信者リンク（4）の方が同じ層に直接届く |
| 誕生日配信・記念配信の記事 | 検索がほぼ無い。特定チャンネルの話になりやすく、YouTube のデータの扱いにも近づく |
| PR チャンネル枠・アプリ内広告・AdSense | 前回レビュー（重大-1〜4）のとおり。YouTube 規約・独自ドメイン・効果の小ささ |
